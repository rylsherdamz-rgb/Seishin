## Seishin Lite (trained assistant in the Agent tab)
- User asked for a chatbot that answers "what's lined up today" etc., kept as "Seishin" (no new name), "train a LM lite so it's small", inside the Agent tab.
- Built a trained intent model instead of a generative LM: a tiny LM would hallucinate the schedule; here the model decides *what* was asked and answers come from the stores. ml/seishin-lite: dataset.py (EN/TL/Taglish templates, typo noise, split by template), features.py (hashed words/bigrams/char-trigrams + cue-word groups), train.py (NumPy MLP 1024→32→10, int8), probe.py (70 hand-written questions). model.json 48.5 KB.
- Iterations: v1 overfit (76% held-out, 20% wrong answers) → more phrasings + openers + stronger weight decay → cue-word groups (+ held-out 82%) → command guard regex + threshold sweep. Final: probe 73% answered itself, 96% exact; held-out wrong-family 0.4%.
- App: src/services/lite (features.ts parity port, model.ts inference, when.ts EN/TL dates & times, answer.ts from events/todos with recurrence + 23:59 rule, index.ts askLite). runAgentLoop asks Lite first (no attachments); provider "lite" shows "Seishin Lite · instant". With no model set up, the "model not loaded" error became the list of things it can answer. Suggestions lead with Lite questions.
- Tests: lite-model (Python parity to 3 dp, probe routing), lite-answer (27: agenda/free/due/overdue/find/next, TL dates, times), lite-agent (no-model path). 238 green.

Reflection: measuring "wrong family" and "actions answered by mistake" instead of raw accuracy made the threshold choice obvious. Next: real user questions from the session log (opt-in, local) would be the best new training data; add "add task" handling once Lite can extract titles reliably.

## Round 2 training ("train it")
- Wrote final_exam.py (79 questions) BEFORE tuning; probe.py became validation.
- Composed questions from parts (opener + frame + object + day + ending), 500/intent, train only. search.py: h{32,48} × epochs{6,10,14} × wd{1e-3,3e-3,6e-3} × 3 seeds on validation. Winner h32 e6 wd3e-3. More composed data (1k/2k) hurt; 3-seed ensemble ≈ best single at 3× size → single.
- Routing now uses family confidence (sum over sched/tasks/chat) at 0.55 — fixes correct-but-split cases ("what's next on my schedule" agenda 0.54 + next 0.43). Mirrored in model.ts; no-model bar 0.3 → 0.4.
- Final exam: round 1 answers 75%, exact 86%, wrong-family 6.3%, actions 3/18 → round 2 answers 71%, exact 95%, wrong-family 2.5%, actions 1/18. Probe test now requires 0 wrong-family / 0 actions.
- Known misses (not tuned against): short help phrasings, "what's 12 times 13" → agenda.

Reflection: writing the final exam first kept the comparison honest — round 2's win is reliability, not coverage. Next data should come from real phrasings, not more templates.
